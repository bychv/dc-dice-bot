# Agent Note: 所有指令回执统一回显使用者

Status: implemented

## 问题

Discord 的斜杠命令**不在频道里留下玩家发言**，而日志只记"玩家行 + 骰娘回执行"：玩家行由 `createLogRecorder` 逐行解析说话人，骰娘回执却是**无主**的——事后翻日志看不出这条是谁发的。改动前各命令各行其是：`/rh` 用 Discord 显示名、`/rc` 等检定命令干脆没有前缀、个别命令自带名字；19 条命令里的一致性问题无法靠逐个补丁解决。

## 决策

- 前缀内容为 `【角色卡名 → 称呼(/nn) → Discord 显示名】`，解析与日志说话人**同一套**（`speakerName`），实现在 `bot/src/bot/handlers/context.ts`：`actorLabel()`、`actorLabelFor()`（按钮流程没有完整 `ctx`）、`actorEcho()`。
- **只在回执出口统一加一层**：`bot/src/bot/adapter.ts` 的 `handleInteraction` → `echoActorLabel()` → `actorEcho()`；按钮分支 `handleButtonInteraction` 同样处理（用 `actorLabelFor`，因为按钮流程没有完整的 `ctx`）。handler **不自己加**。
- **幂等**：`actorEcho()` 见正文已以 `【` 开头就原样返回。`/rcx`/`/rax` 代投刻意以**被代投者**的卡名开头，`/rh` 投进私密子区的那一份不经过出口、自带前缀（`/rh` 的投递规则见 [暗骰投递：无自己局的场景用最近开局的局](../feature/2026-09-30-hidden-thread-falls-back-to-newest-game.md)），两者都依赖这条幂等规则。
- **入日志的口径**：`logBotReply` 跳过 `/log` 指令自身的回执（对应 Dice! `strLowerMessage.find(".log") != 0` 的排除）与 ephemeral 回执（只有发起者可见，不该进公共日志）。
- handler 侧同步拆除：`check.ts` 去掉 `withActor`、`roll.ts` 去掉 `withNick`（`/r`、`/rs` 的 `【称呼】` 并入统一前缀）。

## 测试

`bot/tests/spec/actor-echo.test.ts` 三条：命名字典（无卡用显示名、绑卡后改卡名）、13 条常见命令的回执**逐条**带前缀且只带一层、以及 `actorEcho` 的幂等（`【已有】正文` 不再叠加）。

## 曾考虑的替代方案

**让每个 handler 自己加前缀** —— 改动前的事实状态：`/rh` 用显示名、`/rc` 没有、其他命令各自为政；每加一条命令都要记得补，漏了就静默不一致，改解析链还要改 N 处。已否决。

**只修 `/rc` 一条** —— 能立刻让主力检定指令有主，但日志里其余命令的回执仍然无主，等于把同一个问题留一半。已否决。

**不改回执，改为把 interaction 元数据写进日志** —— 日志里只会多一个 `<@雪花号>`，读日志的人（以及频道里其他成员）仍然不知道"这条是谁发的"；且频道内的可读性没有改善。已否决。

**出口无条件叠加前缀（不做幂等）** —— handler 里已经带了 `【卡名】` 的正文会变成 `【甲】【甲】…`；代投、暗骰私密副本这类"前缀语义不同"的场景也会被污染。已否决。

## 后果

- 收益：19 条命令与二次确认按钮的回执**全部**带使用者，日志里的骰娘行不再无主；此后**新增命令自动享有**该前缀，无需记得加。
- 代价：handler 里**故意**以 `【` 开头的正文会被出口跳过——这是一条**约定**而非类型保证；把正文改成 `【` 开头就会静默改变日志归属的可读性。embed 化回执（如 `/coc`，见 [自动掷调查员卡](../feature/2026-09-29-coc-investigator-rolls.md)）的"是谁"由 `content` 那句说明承载，前缀不写进 embed，免得把使用者名塞进卡面。
- 历史日志里已有的无前缀行**不会**（也无法）追溯补写。
