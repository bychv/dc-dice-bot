# Agent Note: `/stx` 供 KP 查看他人属性

Status: implemented

## 问题

`/st` 只作用于**自己**当前场景生效的那张卡（没卡时会自动建一张）。KP 想核对某位玩家的属性时没有直接手段：

- `/pc show` 也只能看**自己**的卡（它按 `ctx.userId` 取卡）；
- 让玩家逐个报数既慢又容易报错，尤其检定失败玩家质疑成功率时，KP 想立刻确认"你意志到底多少"；
- `/rcx` 能拿被代投者的卡**算**检定，但回执只给结果，看不到完整卡面（主属性、SAN、技能）。

## 决策

新增 `/stx [被查看者] [卡名]`：**只读**查看某人当前场景生效的角色卡，或他名下指定的一张卡。

| 选项 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `user` | USER | 否 | 被查看者；省略就是自己（等价 `/pc show` 的用法，但排版更适合核对） |
| `name` | STRING | 否 | 指定某个卡名（用于一个人有多张卡、或当前场景没绑定时） |

行为：

1. 省略 `name` 时按**与检定完全相同的解析链**取卡（局 → 场景 → 父频道 → 用户级 → 全局），所以 KP 看到的正是"这个人在这个场景里掷骰会用的那张卡"；
2. 排成便于核对的几段：主属性（8 项）、状态（幸运/理智/生命/魔法）、技能与自定义项（按数值降序）、骰式（`/st &沙漠之鹰=…` 存的）、最后一行更新时间；
3. 找不到卡时不是干巴巴报错：列出该用户名下的卡名，提示用 `name:` 指定（当前场景没绑定但卡存在是最常见的情况）；
4. **回执 ephemeral**（只有发起者可见）：属性表比"卡名"更私密（技能、SAN、生命都在内），默认不把它贴进公共频道；这同时让"只有 KP 能看"这件事**在观感上成立**，而不用去猜"谁是这个局的 KP"；
5. 只读：不改卡、不改绑定，也不触发 `/sn` 昵称同步。

## 曾考虑的替代方案

**给 `/st` 加一个 `user` 选项**（同一个命令兼顾查看与修改）。`/st` 的语义是"改我自己的卡"，加 `user` 后"查看"与"改别人卡"只差一个参数，误操作代价太大（改错别人的属性没有撤销）。

**做成公开回执**（像 `/rc` 那样整条发在频道里）。属性表包含 SAN/生命/技能，公开贴出来等于把玩家卡面摊给所有人；KP 核对通常也不希望打断节奏。

**只允许 KP 使用**。Discord 斜杠命令没有可靠的"局内 KP"判据（`/game` 的 KP 是数据不是权限位），要判权只能写死"服务器管理员"，而实际跑团里 KP 往往没有管理权限；用 ephemeral 把可见范围收在发起者身上，比伪造权限检查更诚实。

**用 embed 展示**（像 `/coc`）。属性条目多且长短不一，embed 的 field 会挤成一片；纯文本按行排列更好核对，也更容易整段复制。

**复用 `/pc show` 的输出格式**。`renderSheet` 把所有属性挤在一行里（`k:v  k:v …`），技能多达四五十项时完全没法读；核对场景值得一套专门的排版。

## 测试

- `tests/bot/stx.test.ts` 7 条：看别人的卡、看自己、`name:` 指定、没生效卡列卡名、无卡提示、卡名不存在、只读（卡/绑定/昵称都不动）。
- 线上实跑（部署后）：`/stx user:U2` → `ephemeral=true`，主属性/状态/技能按值降序/骰式/更新时间齐全；`/stx name:不存在` → 列出他名下的卡。

1. `/stx user:@U2`：显示 **U2** 当前场景生效的那张卡，回执 `ephemeral: true`；
2. 省略 `user`：显示自己的卡；
3. `name:` 指定卡名：显示该用户名下的那张卡（不受当前场景绑定影响）；
4. U2 当前场景没生效卡但名下有卡：回执列出卡名并提示用 `name:`，不报"没有角色卡"了事；
5. U2 名下没有任何卡：明确说"该成员还没有角色卡"；
6. 输出含主属性、状态、技能（按值降序）、更新时间；超长时按既有口径截断并注明；
7. 不改变任何数据（卡、绑定、昵称都不动）；
8. 清单/镜像/文档同步为 25 条命令；`npm run check` 通过。

## 后果

- **信息可见范围**：ephemeral 只保证"频道里其他人看不到"，同一服务器内被查看者本人不会收到通知；若日后需要"被查看者知情"，要另加提示。
- **依赖绑定链**：省略 `name` 时看到的是"这个人在这个场景里的卡"，同一人在别的子区可能绑定另一张卡——回执里会带上卡名与更新时间，避免误读。
- **命令数增长**：`/stx` 之后，`x` 后缀的家族（`/rcx` `/rax` `/scx` `/stx`）都在做"以别人的卡为准"，命名一致但命令数到 25 条，仍在 Discord 的 100 条上限内。
