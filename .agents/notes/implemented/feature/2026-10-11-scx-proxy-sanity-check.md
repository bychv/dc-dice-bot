# Agent Note: `/scx` 代骰理智检定

Status: implemented

## 问题

理智检定 `/sc` 只能由本人在自己的场景里掷。实际跑团里常需要**别人替他掷**：KP 说"你看到尸体，掷 SAN"，而玩家此刻不方便操作；或者 KP 想让全桌的理智检定集中在自己手里过一遍。[`/rcx`/`/rax` 代投](2026-09-30-proxy-checks.md) 已经解决了技能/属性检定的代投，但 SAN 检定**不能照搬**：

- 走的是不同的引擎：`/rcx` → `coc.check`（读卡算成功率，不改卡）；`/sc` → `coc.sanity`（**会改卡**：SAN 减少，可能带临时疯狂/不定性疯狂）。
- 因此"代骰"必须明确：**理智扣在被代骰者的卡上**，而不是发起者的卡上；否则一次代骰会把 KP 自己的 SAN 扣掉。
- 卡面一变，`/sn` 统计昵称里显示的 `SAN` 就过期了——`/st` 已有"属性一变就刷新昵称"的钩子，SAN 掉点走的是同一条需求。

## 决策

`/scx [被代骰者] <原文>` 已交付，与 [`/rcx`/`/rax` 代投](2026-09-30-proxy-checks.md) 同一族命名与口径：

| 选项 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | STRING | 是 | 与 `/sc` **完全相同**的整行原文（例如 `1/1D6`、`1D3/1D10`），解析器同一套 |
| `user` | USER | 否 | 被代骰者；**省略就是给自己骰**（等同 `/sc`） |

行为：

1. 用**被代骰者**在当前场景的角色卡（解析链同 `/rc`：局 → 场景 → 父频道 → 用户级 → 全局）解析 SAN 与检定；
2. **理智变化写回被代骰者的卡**（`store.putSheet(targetId, result.sheet)`）；
3. 回执以**他的角色卡名**开头（`【卡名】…`，角色卡名 → 称呼 `/nn` → `<@id>` 兜底），代骰时末尾补一行 `（由 <@发起人> 代骰）`——斜杠命令不进日志，不写就看不出是谁替他骰的；
4. 由于回执已以 `【` 开头，适配层幂等的 `actorEcho` 不会再叠一层发起人的名字（与 [回执统一回显使用者](../architecture/2026-09-20-receipts-echo-the-actor.md) 的幂等规则同源）；
5. 本场景正在记录、且该成员开了 `/sn` 时**刷新他的统计昵称**；失败只附一行警告，**理智照常记在他卡上**。

配套重构：`/st` 里那段"属性一变就刷新统计昵称"已抽成 `nickSync.refreshStatNicknameNote()`，由 `/st`、`/sc`、`/scx` 共用（`/sc` 因此也获得同样行为：自己掉 SAN 时昵称跟着变，与 [统计昵称同步](2026-09-29-nickname-sync.md) 的钩子同源）。

清单与文档：`scx` 进入注册清单（23 → 24 条命令）；文档新增 **§9.2**（`/sc` 所在的 §9.1 之后），原 §9.2 `/ti` `/li`、§9.3 `/en` 顺延为 §9.3 / §9.4，`src/coc/improve.ts` 里对 §9.3 的注释引用同批改为 §9.4。

## 测试

`bot/tests/bot/check-proxy.test.ts` 用**真实 coc 引擎**（`createCocRules` + `FixedRng`）锁住这四条：

- `/scx user:@U2 text:1/1D6`：理智**落在 U2 的卡上**（60 → 59），**发起者的卡分毫不动**；
- 省略 `user` 等同 `/sc`（以自己卡名开头、无代骰行）；
- 被代骰者没有卡时前缀用 `@他` 兜底，不张冠李戴；
- 被代骰者开了 `/sn` 且本场景正在记录时，回执附"已更新统计昵称"，昵称里的 `SAN` 随之改变。

线上实跑（部署后、真实引擎，2026-10-11）：`/scx user:U2 1/1D6` → `【二宫友梨】理智检定 D100=50/60 → 成功，理智变化 -1；理智 60→59`，同时 `KP1` 的理智保持 70；`/scx user:U2 0/1D6`（骰 90 失败）→ `理智 30→26` 并附 `已更新统计昵称：二宫友梨 |DEX45 HP12/12 SAN26`。注册复核：两个服务器各 24 条命令、`/scx` 选项 `text`(必填) / `user`，中文本地化正常。提交 `14605c6`，`bot` 测试 735/735。

## 曾考虑的替代方案

**直接把 `/scx` 做成 `/rcx` 的别名**。最省事，但 `/rcx` 走 `check` 引擎、**不写回卡**，代骰出来的结果不会扣任何人的 SAN——连"替别人掷"的主要用途都达不到。

**代骰但不改卡，只把结果给 KP 看**。等于一个"预演"，与 `/sc` 的语义（SAN 真的掉）冲突；KP 还要手动 `/st` 补记，正是这一步最容易漏。

**把 `user` 设为必填**。与 `/rcx` 的可选口径不一致，且"省略=给自己骰"无害（等价 `/sc`），强制填反而多一次交互。

**不刷新统计昵称**。`/sn` 的昵称里带 `SAN`，代骰掉点后昵称会长期显示过期数值——那看起来就是 bug。

**给 `user` 加权限限制（只有 KP 能代骰）**。Discord 斜杠命令没有可靠的"局内 KP"判据（`/game` 的 KP 是数据不是权限），而且 PL 之间互相代骰（"帮我看一下"）也是正当用法；代骰者的身份会在回执与 Discord 交互记录里公开，先用透明而不是门禁。

**新增独立命令名 `/sanityx` / `/sc-proxy`**。与 `/rcx` 家族命名不齐，且 Discord 命令名要短、好按；`x` 后缀已经在 `/rcx` 上表示"代"。

## 后果

- 收益：KP 能替玩家过理智检定，结果直接落在**被代骰者**的卡上并带全套疯狂判定；回执注明代骰者，日志里看得出是谁替他骰的；SAN 变化即时反映到统计昵称。
- 代价与现状：代骰**不做权限门禁**，只做透明（回执 + Discord 交互记录）；若日后被滥用，需要一个新的决策来加白名单。代骰路径会对**其他成员**发起改名调用（需要 bot 具备「管理昵称」权限）：线上复核（2026-10-11）「玩原神导致的」已开该权限，改名实际生效（曾出现"当前昵称已经是目标值，无需改动"的幂等命中）；「下艺同好会」未开，那条路径静默失败——与 `/sn` 既有行为一致。
- 文档编号顺延只影响 `src/coc/improve.ts` 一处注释引用，已同批修正；§9 之后的编号与正文对应关系保持一一对应。
- 最容易写错的地方（把理智扣到发起者卡上）现在由测试与线上验证双重守住：`check-proxy.test.ts` 断言发起者卡不变，线上实跑同样复核过。
