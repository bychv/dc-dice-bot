# Agent Note: `/rcx` `/rax` 代投检定

Status: implemented

## 问题

技能/属性检定 `/rc` 只能给自己掷，但桌上经常要**替别人投**：KP 说"你过个聆听"，玩家在忙；或者玩家口述、KP 代按。Discord 侧还多一层麻烦：**斜杠命令不在频道里留下玩家发言**，日志只记骰娘回执——如果回执按"发起人"归属，日志里就变成了 KP 自己在检定，看不出是谁的卡。

## 决策

`/rcx`（及同义命令 `/rax`，`x` 表示"代"）已交付：

| 选项 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | STRING | 是 | 与 `/rc` **完全相同**的整行原文（解析器同一套） |
| `user` | USER | 否 | 被代投者；**省略就是给自己投**（等同 `/rc`） |

1. 用**被代投者**在当前场景的角色卡解析属性/技能（解析链同 `/rc`：局 → 场景 → 父频道 → 用户级 → 全局）；
2. 回执以**他的角色卡名**开头（角色卡名 → 称呼 `/nn` → `<@id>` 兜底），代投时末尾补 `（由 <@发起人> 代投）`；
3. 因回执已以 `【` 开头，适配层幂等的 `actorEcho` 不会再叠发起人的名字（见 [回执统一回显使用者](../architecture/2026-09-20-receipts-echo-the-actor.md)）；
4. **只读卡、不写卡**——这一点是它与 [`/scx` 代骰](2026-10-11-scx-proxy-sanity-check.md) 的分界：理智检定会改卡（SAN 减少、可能带疯狂），所以那条命令必须把结果写回被代骰者，而属性/技能检定没有需要落地的状态；
5. 房规（`/setcoc`、局/群默认）取**发起者所在场景**，与 `/rc` 相同；`user` 省略时行为与 `/rc` 完全一致。

## 测试

`bot/tests/bot/check-proxy.test.ts` 同时用两种环境锁住语义：

- **stub 引擎**：断言传进引擎的 `sheet` 是**被代投者的卡**、房规取发起者场景，且回执前缀/代投行正确；
- **真实 coc 引擎**（`createCocRules` + `FixedRng`）：U1 力量 60、U2 力量 30，`/rcx user:@U2 力量` 的结果里必须出现 `/30` 而不是 `/60`——这是"真的用了他的卡"最直接的证据。

另覆盖：`/rax` 与 `/rcx` 行为一致、省略 `user` 等同 `/rc`（无代投行）、被代投者没卡时用 `@他` 兜底、引擎报错也带他的前缀。

## 曾考虑的替代方案

**回执按发起人归属，只在末尾注明代投**。这样日志里"谁在检定"会读成 KP，与他实际只是在代人按骰的事实相反；用户明确要求"回显被代投的人使用的角色卡名"，前缀归被代投者是唯一读得通的写法。

**把 `user` 设为必填**。与"可以选择一个人代替他投"的表述不符：省略即给自己投，等价 `/rc`，没有歧义；强制填反而让本来只想自己掷的人多一次交互。

**不新增命令，直接给 `/rc` 加一个 `user` 选项**。`/rc` 是主力检定命令，加一个只在代投时有意义的选项会污染最常见的路径；且别名 `/ra` 也要跟着长一个选项。独立命令族的代价是多两条注册项，换来"想代投才用得到"的清晰语义。

**只做 `/rcx`，不给 `/rax`**。它们是一条命令的两种名字（Discord 没有命令别名机制，`/rc`/`/ra` 也是这么处理的），只留一个会让两套命名不对称。

**不做代投，KP 口头转述**（当时的现状）。正是这条促使了本决策：KP 转述时既容易记错成功率，也没人分得清卡面变化到底记在谁头上。

## 后果

- 收益：KP 能替玩家投，回执与日志都指向**被代投者**，同时保留"谁代投的"这一事实；`text` 与 `/rc` 同解析器，玩家/KP 学一套语法即可。
- 代价：**代投没有权限门禁**——任何人在任何场景都可以替别人投并回显对方卡名。当前靠 Discord 交互记录与回执里的代投行实现透明，而非阻止；若日后需要白名单，应另开决策（同为 [`/scx`](2026-10-11-scx-proxy-sanity-check.md) 的现状）。
- 被代投者没有卡时，前缀退化为 `@他`，引擎的报错也带这个前缀——不会再出现"看不出是谁的卡有问题"。
- 命令数 +2（21 → 23），随后 `/scx` 复用同一套前缀、代投行与兜底口径（23 → 24），两条命令的差异只剩"是否写回卡"。
