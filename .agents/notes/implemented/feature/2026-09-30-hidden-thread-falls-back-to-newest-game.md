# Agent Note: 无自己局的场景，暗骰投给「最近开局的局」

Status: implemented

## 问题

暗骰 `/rh` 需要一个"投到哪个私密子区"的答案。开局一般在**单独子区**里（`/game start` 默认新建主场景子区），而同一服务器里的几个局**常常共用同一个父频道**——于是出现两个互相矛盾的既有规则：

- 子区没有自己的场景指针时会**继承父频道的局**（`handlers/context.ts: sceneGameId`），这让"跨子区继续用同一局"成立；
- 但父频道指针**只能指向其中一个局**，而且它是"最后一次在父频道 `/game start`/`switch` 的那个"，往往停在很久以前的局上。线上实测：父频道指针停在 `#1 test`（09-17 建的测试局），真正在玩的是 `#5 东乡村`（10-01 开），于是**父频道下任何非本局子区里的 `/rh` 都投进了测试局的暗骰区**，KP 在自己团的暗骰区里看不到这次暗骰。

同时，父频道级的 `/rh` 登记（`threads.json`）也会把同一个陈旧目标钉住。

## 决策

`/rh` 解析投递目标时区分「**本场景自己的局**」与「**继承来的局**」，优先级固定为：

1. 本次显式 `thread:`（登记并复用，绝不静默改投）；
2. **本场景自己绑定的局**的暗骰子区——`getSceneGame(ctx.channelId)`，或这个频道/子区本身就是某局的 `sceneThreadId` / `hiddenThreadId`（反查，防止指针被 `/game switch` 改走后张冠李戴）；
3. 场景级 `/rh thread:` 登记；
4. **本服最近开局的 active 局**的暗骰子区——判据只看局本身：`status === 'active'`、有 `hiddenThreadId`、`startedAt` 最新；`startedAt` 相同时取**局号更大**的（时钟被冻结或同一秒连开两局时的稳定判据）；
5. 自动创建 `暗骰 · <场景名>`（父频道下，创建后按场景缓存复用）。

第 4 条**覆盖**"子区继承父频道指针"，但**不覆盖**第 2、3 条：显式绑定与显式登记永远赢。回复里会写明原因：`本场景没有开局，已按**最近开局的局**默认投到 #5 东乡村 的暗骰子区（可用 /rh thread:<子区> 为本场景单独指定）`。

目标失效（子区被删 / Bot 被移出）时按候选的 `owner` **精确清理**：清掉那一局的 `hiddenThreadId` / 那条场景登记，再继续回落；顺带把此前只收集、从不显示的失效提示（`invalidated`）补进回执与降级回执。

判据**不看日志开关**：`/log off` 只是暂停这个场景的记录，不代表团不在跑。

## 测试

- `bot/tests/bot/rh.test.ts` —— 20 条，覆盖：借用与不借用、自己局不被覆盖、父频道指针被覆盖、显式登记优先、日志 off 照借、局 ended 不借、目标失效清理回落。
- 用**线上真实数据副本**（`data/*.json` 复制到临时目录）跑过：无局子区 → `#5 东乡村`；`#5` 自己的主场景子区 → `#5`；父频道本身（指针 `#1`） → `#1`。

## 曾考虑的替代方案

**只在"父频道也没有局"时才借用**（第一版实现）。规则最保守，不触碰既有的继承语义；但线上布局里所有局共用一个父频道、父频道永远有指针，这条**永远不触发**——正是它让 `#1 test` 继续吸走 `#5` 东乡村的暗骰。已否决。

**要求"有 `on` 日志"才算正在进行**（第一版判据）。听起来更贴合"正在进行"，实际上把判据绑到了一个容易误读的信号上：`#5 东乡村` 开局后日志是 `off`（正常操作），于是它被排除，反而选中了仍留着测试日志的 `#2 测试骰娘`。日志开关表达的是"这个场景此刻记不记录"，不是"这个团在不在跑"。已否决。

**按"最近有日志活动"（最新一条 on 日志的 `startedAt`）排序**。对"日志长期挂着 on 的老局"仍然失准（`#1 test` 有三条 on 日志），且需要按局逐个查日志。已否决。

**按父频道亲和度优先（同父频道的局优先）**。在"所有局共用一个父频道"的布局里所有候选打平，等于没有判据；而在父频道有指针的场景里它又轮不到生效。降级为无用代码后删除。

**让父频道自己也走"最近开局的局"**（即连场景指针也放宽到只对子区严格）。会让父频道的 `/log`、`/pc`、房规等**一整套**上下文与 `/rh` 指向不一致，代价远超收益。保留为可选后续，不在本次决策内。

## 后果

- 收益：几个局共用一个父频道时，非本局子区里的暗骰终于落到"现在在打的团"；KP 在一个暗骰区里看完整团；显式绑定与显式登记仍然说了算，不会出现"我明明指定了却被改投"。
- 代价：引入"最近开局的局"这个隐式默认——**同时开两个团**时，只有后开的那个会被非本局子区默认选中；另一个团需要显式 `/rh thread:` 或在自己的子区里掷。判据是"局"级而非"场"级，跨父频道的子区也照此规则（不再有父频道亲和度）。
