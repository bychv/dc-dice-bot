# Agent Note: `/sn` 统计昵称同步（开 log 改名、log off 改回）

Status: implemented

## 问题

跑团时"这张卡现在什么状态"（敏捷 / 生命 / 理智）要么逐个问、要么翻角色卡；而 Discord 的**服务器昵称**恰好是一个人人可见、机器人可写（有「管理昵称」权限时）的展示位。此前 bot 完全没有把昵称与卡面联系起来的机制：玩家在频道里的标识始终是入场时随手设的昵称，与卡上数值无关。

## 决策

- `/sn on|off|show`，**服务器级、按用户开启**（DM 内拒绝：昵称本身是每服独立的）。
- 触发时机：`/log new`、`/log on`、`/game start` → 给本服所有已开启 `/sn` 且**当前场景能解析到角色卡**的成员改名；`/log off`、`/log end`、`/game end`（本场景不再有 `on` 日志时）→ 改回原名；`/st` 改完属性后**立刻**刷新该成员。
- 昵称格式 `角色名 |DEX70 HP12/12 SAN70`：HP 上限 = `floor((体质+体型)/10)`，算不出上限就只显示当前值；缺项省段；Discord 昵称上限 32 字符，超出时截断角色名、保留统计段（`bot/src/bot/handlers/nickSync.ts`：`statNickname()`、`maxHpOf()`、`NICK_LIMIT`）。
- **幂等**：结果已等于目标值就不写（不产生多余的 Discord 调用）；**只在第一次改名时记原名**（`NickSyncState.original`），换卡重同步不会把统计昵称当成"原名"。
- **失败隔离**：单人失败（缺「管理昵称」权限 / 服务器所有者 / bot 角色层位低于对方）只记进回执，不影响其他人；**改名失败就撤回刚记下的 `original`**，否则之后每次 `log off` 都会去"还原"一个从没改过的昵称、白报一行失败。
- `/sn off` 对"改不回来"**静默处理**：直接回复"已关闭统计昵称同步"，不回显 Discord 报错（服务器所有者永远改不了，报错只是噪音）。
- 存储：`misc.json → nickSync`（键 `guildId + userId`），能力接口 `NickSyncStore`（`bot/src/store/extras.ts`，jsonStore 与测试替身都实现）；平台能力 `Platform.memberNickname` / `Platform.setMemberNickname`（`contracts/bot.ts`，`adapter.ts` 用 discord.js 实现）。

## 测试

`bot/tests/bot/nick-sync.test.ts` 26 条：格式与截断、开关与预览、记录中 `/sn off` 恢复原名且不影响日志、关闭后 `log on`/`st` 不再改、权限不足时开启报错但保留开关且不留还原点、权限不足时关闭静默、`log off` 不白报失败；`/st` 那组用**真实 coc 引擎**（bot 层默认替身只回"已处理 …"，测不出属性变化）。

## 曾考虑的替代方案

**每次掷骰时临时改名、掷完改回** —— Discord 调用翻倍，且中途崩溃/断线会把统计昵称**留在服务器上**，反而需要人工清理。已否决。

**只在回执或 embed 里显示状态，不改昵称** —— 等于回到"要翻卡才看得到"，没有解决动机。已否决。

**权限不足时报错并回滚开关** —— 用户要求静默关闭：服务器所有者永远无法被 bot 改名，报错只会反复打扰。已否决。

**改名失败仍保留 `original`** —— 会在 `log off` 时去还原一个从没改成过的昵称，白报失败（线上正是这么暴露出来的）。已否决。

**把统计昵称当"原名"记下来** —— 换卡后第二次改名会把统计昵称写进 `original`，从此再也还原不回真正的原昵称。已否决。

## 后果

- 收益：开 log 时全桌昵称自动变成卡面速览，`/st` 掉血/掉 SAN 即时反映，`log off` 恢复原名。
- 代价与现状：需要 Bot 具备**「管理昵称」**权限——线上复核（2026-10-11）：「玩原神导致的」**已开**（日志里可见"已同步/已还原 1 位成员的统计昵称"），「下艺同好会」**仍未开**（那里 `/sn on` 会回 `Missing Permissions`）；**服务器所有者**永远无法被 bot 改名。
- 只影响**当前服务器**的昵称，不改全局显示名；依赖 log 生命周期钩子，`/st` 那条是额外加的（见 [日志生命周期](2026-09-30-log-lifecycle-resume-and-export.md)）。
